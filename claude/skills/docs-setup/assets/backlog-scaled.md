### `{{DOCS_DIR}}/backlog/` — やること（1タスク1ファイル）

- ファイル名: `task-<3桁連番>-<英小文字kebab-case要約>.md`
- **1タスク = 1セッション = 1PR** で終わる大きさにする。終わらないなら分割する
- 実装計画は **着手直前** に書く（先に書くとコードベースの現状とずれる）
- 実装計画を書いたら、**人間の承認を待ってからコードを書く**
- `status: done` になったら `{{DOCS_DIR}}/backlog/archive/` へ移動し、INDEX の完了欄に移す
- **エージェントはまず `INDEX.md` だけを読む。** 個別ファイルは関係するものだけ開く

#### テンプレート

```markdown
---
id: task-012
title: 検索APIの追加
status: todo        # todo | doing | review | done
owner: @username
created: 2026-07-25
updated: 2026-07-25
depends_on: [task-009]
related_decisions: [ADR-0007]
---

## 背景 / なぜやるか
（1〜3文。ユーザー価値または技術的必然を書く）

## スコープ外
- （エージェントの探索範囲を明示的に区切る。ここが一番効く）

## 受け入れ条件
- [ ] `GET /search?q=` が200とJSON配列を返す
- [ ] 該当なしのとき空配列を返す（404にしない）
- [ ] 単体テストが `npm test` で通る

## 実装計画
（着手直前に記入。承認後にコードを書く）

## 作業メモ
（詰まった点・判断したこと。冗長なログは書かない）

## 完了サマリ
（何を変えたか3行以内。ここが将来の一次情報になる）
```

#### `INDEX.md`

1エントリ1行を厳守します。ファイルを追加・状態変更したら、**同じコミットで INDEX を更新**します。

```markdown
# Backlog INDEX

## 進行中
| ID | タイトル | Status | 更新日 | 概要 |
|---|---|---|---|---|
| task-012 | 検索APIの追加 | doing | 2026-07-25 | 全文検索エンドポイントを新設 |

## 完了（archive/）
| ID | タイトル | 完了日 | 概要 |
|---|---|---|---|
| task-009 | インデックス設計 | 2026-07-20 | tsvector 列を追加 |
```

#### アーカイブ

- 完了したタスクは `archive/` へ移す。**中身は消さない**
- `archive/` の INDEX 行が増えて読みにくくなったら、古いものから削ってよい（git に残る）
- 連番は振り直さない
