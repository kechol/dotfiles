## ドキュメント運用ルール

このリポジトリのドキュメントの書き方は、ここに書かれたルールだけが定めます。
ドキュメントを作成・更新する前に必ず読んでください。

### 考え方

**台帳は「何があるか」だけを持ち、「なぜそうしたか」は {{RATIONALE_HOME}} に置きます。両者は ID で結びます。**

台帳に理由を書き始めると肥大し、肥大すると人もエージェントも読まなくなり、読まれない台帳は嘘をつき始めます。
ID で結んでおけば台帳は小さいまま保たれ、理由は `git log --grep` でいつでも復元できます。

### 置き場所

{{LAYOUT_TREE}}

- **リポジトリ直下に新しい `.md` を作らない。**
  直下に置いてよいのは `README` / `CLAUDE` / `AGENTS` / `CONTRIBUTING` / `CHANGELOG` / `LICENSE` のみ。
- 上記以外の置き場が必要になったら、勝手に作らず **まず相談する**。

上のルールが対象にするのは **台帳** です。ドキュメントにはこれ以外の系統もありえます——
実装から書き起こした **リファレンス**（「今どうなっているか」を書く文書）や、凍結した **原本・記録**。
役割が違うので、台帳の書式や追記ルールをそちらに適用しないでください。
リファレンスは実装に追従して書き換えるもの、原本は変更しないものです。

### 禁止事項

- 直下への新規 `.md` 作成
- `SUMMARY.md` `NOTES.md` `PLAN.md` `TEST_RESULTS.md` のような汎用名のファイル
- 同じ内容を複数の場所にコピーすること（必ずリンクで参照する）
- **台帳に理由を長く書くこと。** 3行を超えたら {{RATIONALE_HOME}} に移す
- **commit メッセージを `更新` `fix` `wip` で済ませること**（台帳が参照先を失う）
- コードを読めば分かることを書くこと。書くのは **why** だけ
- {{AGENT_FILE}} から台帳を `@import` すること
  （毎セッション全文がコンテキストに載るため。都度読ませる）

### セッション中のチェックリスト

- [ ] **開始時**: 台帳（{{LEDGER_LIST}}）を読んだ
- [ ] **実装前**: 既存の決定に反していないか確認した／必要なら決定を Proposed で追記した
- [ ] **実装前**: 着手するタスクに実装計画を書き、承認を得た
- [ ] **実装後**: 受け入れ条件を更新した
- [ ] **PR前**: 台帳の状態を更新し、commit に `Task:` / `Decision:` trailer を付けた
- [ ] **PR前**: 直下や想定外の場所に `.md` を作っていないか確認した

### 機械的な強制（推奨）

指示文だけでは遵守は安定しません。以下を併用すると実効性が大きく上がります。

- **CI チェック**: 直下の `.md` 追加、命名規則違反、INDEX とファイル一覧の不一致を検出して落とす

```bash
# 例: 許可リスト外の直下 .md を検出
git diff --name-only origin/{{DEFAULT_BRANCH}}...HEAD \
  | grep -E '^[^/]+\.md$' \
  | grep -vE '^(README|CLAUDE|AGENTS|CONTRIBUTING|CHANGELOG)\.md$' \
  && { echo "直下に .md を追加しないでください。{{DOCS_DIR}}/ を使ってください"; exit 1; } || true
```

- **PreToolUse フック**（Claude Code）: 直下への `.md` 書き込みをツール実行前にブロックする
- **path-scoped rule**: `.claude/rules/` 配下のルールに `paths: ["{{DOCS_DIR}}/**/*.md"]` を指定しておくと、
  該当パスを触るときだけ詳細ルールが自動でコンテキストに入る
