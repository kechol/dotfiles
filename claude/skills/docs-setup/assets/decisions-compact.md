### `{{DOCS_DIR}}/decisions.md` — 決めたこと

**1決定 = 1行。追記のみ。** 新しい決定は末尾に足します。

- **既存の行は書き換えない。** 唯一の例外は Status 部分だけ
- 覆すときは新しい行を追記し、古い行の Status を `Superseded by D-011` に変える
- 番号は欠番なしの連番。振り直さない
- **理由・却下案・影響は書かない。commit メッセージに書く**

#### 書式

````markdown
# Decisions

理由・検討した代替案・影響は commit メッセージに記録しています。
`git log --grep='Decision: D-003'` で参照してください。

- **D-001** (2026-07-12, Accepted) TypeScript + Node 22 を採用
- **D-002** (2026-07-15, Accepted) パッケージマネージャは pnpm に統一
- **D-003** (2026-07-20, Accepted) 主データストアに PostgreSQL を採用
- **D-004** (2026-07-22, Superseded by D-011) セッションを JWT で保持
- **D-005** (2026-07-25, Proposed) 検索は Postgres 全文検索で内製する
````

Status は `Proposed` / `Accepted` / `Superseded by D-NNN` / `Rejected` のいずれか。

#### 書くべきもの

言語・FW・DB・外部サービスの選定 / 公開 API の形やデータモデル / 認証認可 /
エラー処理・リトライ方針 / ディレクトリ構成の原則 / **あえて採用しなかった案**

#### 書かなくてよいもの

変数名 / 影響がファイル内に閉じる、いつでも戻せる変更 / パッチバージョン更新

#### 分割を始める基準

1行運用なので長持ちします。以下を超えたら `{{DOCS_DIR}}/decisions/`（1決定1ファイル）への分割を検討します。

| 基準 | しきい値 |
|---|---|
| 決定の数 | 80件を超えた |
| ファイル行数 | 300行を超えた |
| Superseded の数 | 10件を超えた（履歴が読みにくくなっている合図） |

分割の前に、**1行のまま残して詳細だけをエリア別ファイルに逃がす**中間形も有効です
（台帳は `decisions.md` のまま、長文が要る決定だけ `decisions/<area>.md` に本文を置く）。
台帳を1つに保てるので、`git log --grep` の起点が分散しません。

移行は一度にやり、**ID は絶対に振り直しません**。`D-003` → `0003-<kebab>.md`（ADR-0003）と番号を保ち、
対応関係をこのルールに1行残します（過去の `git log --grep` が読めなくなるため）。
