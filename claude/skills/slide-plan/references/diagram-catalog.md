# 図解カタログ（主張の型 → 図解の対応）

各スライドの「図解ナッジ」を書くための引き。**主張の型**を見て図解の型を選び、
「何を軸に、何を並べ、どの1点を強調するか」まで具体化してナッジに落とす。
実際の作図は後段の実スライド化（Marp / PowerPoint / HTML 等）が担うので、ここでは **何を図解すべきか** の判断に集中する。

> 後段の作図制約を軽く意識する: 複雑すぎて組みにくい図（要素が多い・線が交差する）は、
> 構成段階で「要素を減らす／2枚に割る」方向のナッジにしておくと、どの形式で作っても後工程が楽になる。

## 1. 文章か図解かの判断

安易に全部を図にしない。**箇条書き（テキスト）で十分か**をまず問い、図解が効くのは
「関係性・流れ・対比」がある箇所に限る。

- **箇条書き向き**: 並列関係（「A であり B でもあり C」→ ・A ・B ・C）。順序も関係もない列挙。
- **図解向き**: 要素間に**関係・流れ・対比・重なり・階層**があるとき。図解の効果は「見た瞬間に把握できる」こと。
- **手順**: まずタイトル＋リード文（箇条書き）で骨格を組み、テキストだけで分かりにくい箇所にだけ図を足す。

図解ナッジには「この主張は関係性があるので図解／これは列挙なので箇条書きで十分」の判断も書く。

## 2. 主張の型 → 図解 対応表

| 主張の型（言いたいこと） | 適した図解 | ナッジの書き方の例 |
| --- | --- | --- |
| 項目間の違いを整理・比較したい | **比較表（マトリクス）** | 「自社/競合3社 × 評価軸5項目の比較表。自社が優位な行を強調」 |
| 2つの観点で分類・優先順位付けしたい | **2×2 象限図** | 「価格×機能網羅性の2軸。自社を右上象限に配置」 |
| 要素に重なり・共通点がある | **ベン図／集合図** | 「3事業の重なりに『共通基盤』を置く」 |
| MECE に分解／親子・階層を見せたい | **ツリー／ピラミッド図** | 「売上を3要因に分解するロジックツリー」 |
| 誰が誰と繋がっているか | **相関図** | 「関係者4者を線で結び、資金と情報の流れを矢印で」 |
| 手順・業務フローの順序 | **プロセス図／フローチャート** | 「申込→審査→契約の3ステップ、矢印で左→右」 |
| 繰り返し発生する営み | **循環図** | 「Plan-Do-Check-Act の4円環」 |
| 段階的な変化・成熟 | **段階図（ステップ／階段）** | 「導入期→拡大期→定着期の3段の階段」 |
| スケジュール・並行タスク | **ガントチャート** | 「Q1〜Q4 × 4施策の帯。クリティカルパスを強調」 |
| 期首→期末の増減内訳 | **ウォーターフォール図** | 「前期売上→増要因→減要因→当期売上」 |
| 数量の大小比較（絶対値） | **棒グラフ** | 「5製品の売上棒グラフ。自社バーだけ色を変える」 |
| 時間経過による推移 | **折れ線グラフ** | 「3年の月次推移。転換点に注釈」 |
| 全体に対する構成比 | **円グラフ（項目5以内）／横帯** | 「市場シェア。自社セグメントを強調」 |
| 2要素の相関 | **散布図** | 「価格と満足度の相関。外れ値に注釈」 |
| 正確な個別数値を見せたい | **表** | 「料金表。行=プラン、列=機能」 |

- 情報の性質が違えば図形を使い分ける（概念は丸、登場人物は四角 など）。まずは「丸/四角・テキスト・線」だけで組み、装飾は後回し。
- 図解の三要素は「カラー・フォーム（形）・ポジション（配置）」。

## 3. 因果を表す図解の派生型

「原因と結果の数」で図解の形が変わる。因果を語るスライドではこの型から選ぶ。

| 因果の構造 | 図解型 | ナッジ例 |
| --- | --- | --- |
| 因果関係のない同階層の列挙 | **列挙型** | 「独立した3施策を横並び」 |
| 1つの結果に複数の原因 | **背景型（合流に近い）** | 「解約増の背景に3要因を集約」 |
| 1つの原因が複数の結果へ | **拡散型** | 「価格改定が波及する3つの影響」 |
| 複数の原因が1つの結果へ | **合流型** | 「3つの投資が1つの成果に統合」 |
| 時系列の順序 | **フロー型** | 「申込→審査→契約」 |
| 循環 | **回転型** | 「PDCA」 |

図解は「おしゃれに見せるため」ではなく、伝えたい内容の構造に合わせて型を選ぶ。図解はセンスではなく構造であり、学習で習得できる技術。

## 4. スライドの頻出型と1枚の共通骨格

実務で使われるスライドは少数の型に集約される。迷ったら **論証テーブル**（課題→現状→打ち手 の3列で1行ごとに論理を完結）から始める（ビジネス資料の最頻出型）。図解ナッジを書くとき、このどれに当たるかを意識する。

| 型 | 用途 |
| --- | --- |
| **論証テーブル** | 「課題→現状→打ち手」の3列。表を見なくても上の行だけで結論が読める |
| **データチャート** | グラフは証拠。主張ありきで必ず So What? 注釈を添える |
| **○×比較** | 評価軸を統一し、結論が視覚的に分かる配置 |
| **絵解き（コンセプト図）** | 初見で全体像を数秒で掴む。要素は4〜7に限定 |
| **フレームワーク** | 多数候補の「絞り込み理由」を示す |
| **ロードマップ** | スイムレーン型で主体と期限を明示 |
| **中扉（セクション扉）** | 長い資料での区切り・リセット。情報は4つ以内 |

**1枚の共通骨格**（構成案の各スライドに反映する）:

- **タイトル**: 何の話か（短く、14〜20 字）
- **リード / ヘッドメッセージ**: 主張を1行で言い切る（体言止めを避ける／`storytelling.md` 参照）
- **ボディ**: 表・図・グラフはここだけ
- **出典**: 数値・引用があるページには必ず付ける

## 5. 表・グラフの選び方

- **表 vs グラフ**: 正確な数値そのもの → 表。全体の傾向・変化を直感的に → グラフ。
  数値の増減をアピールしたいときだけグラフ、しないなら表で十分。
- **棒グラフ**: 項目間の大小比較。**0 起点厳守**、立体化・非ゼロ起点は避ける。縦棒＝時系列、横棒＝順位付け・長いラベル。
- **円グラフ**: 構成比、項目 5 つ以内。時系列の割合比較には不向き（避ける傾向）。
- **折れ線**: 時間推移。**散布図**: 2 要素の相関。
- グラフで使う数字は実数値・構成比・指数値の 3 種を混在させない。
- 余計な目盛り・単位はカットし本題を強調。グラフのメッセージは色と添え書きで。

## 6. 図解に落とす手順（要素分解）

1. **要素を書き出す**（情報整理）: 伝えたい要素を洗い出し、不要を削る。ここで構成の8割が決まる。
2. **グルーピング**: 関連要素を枠・背景・区切り線・余白でまとめる（階層は1段とは限らない）。
3. **関係性を判定 → 型を選ぶ**: 比較/流れ/重なり/階層 のどれか。上の対応表で図解型を決める。
4. **配置と強調**: 色は3色程度、重要度をサイズ・アイコンで（作図の詳細は後段に任せる）。

## 7. レイアウト・強調の基本（構成段階で意識する分）

作図の細部は後段の実スライド化に任せるが、構成を考える段階でも次は押さえておく。

- **デザイン4原則**: 近接（関連要素を近づける）・整列（揃える）・反復（同じ表現を繰り返す）・対比（重要要素を際立たせる）。
- **視線誘導**: 「見せる」資料は **Z 型**（左上→右上→左下→右下、最重要は左上・行動喚起は右下）。「読ませる」資料は **F 型**（見出し左寄せ、重要語を文頭）。
- **減らす＋整える**: 要素を厳選し（減らす）、レイアウト・フォント・色を統一する（整える）。
- **色は 2〜3 色に絞り、意味を持たせる**。強調は重要メッセージのみ。ジャンプ率（見出し/本文の比）1.4 倍以上で階層を明確に。
- 1スライドの要素グループは詰め込みすぎない（多いなら分割 → 構成に反映する）。
