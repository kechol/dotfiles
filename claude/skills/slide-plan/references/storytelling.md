# 構成・ロジック設計リファレンス

スライド構成案を組むときの論理設計の原則集。構成を複数案つくる（フロー 3）ときの引き出しと、
出す前の自己検証（ピラミッド・MECE・So What?/Why So?）に使う。

## 1. メッセージの構造化

- **ピラミッド構造**: 頂点に最重要の結論（メインメッセージ）を置き、その下に根拠・データを階層的に積む。
  結論から先に伝え、根拠へ降りる。背景→分析→結論の順は、結論に達する前に聞き手が離脱する。
- **1スライド1メッセージ**: 1枚に主張を2つ以上詰めない。「and（しりてが接続）」で主張をつながない。
  余白が増えても2枚に割る。
- **単体で報告書として通用するか**: スライドの価値基準は「その場でウケるか」ではなく「後で読み返しても結論に同意できるか」。
- **分量の目安**: 表紙・目次を除き本論 30 枚前後（60〜90 分）、1枚あたり約 3 分、箇条書きは1枚5行まで。
  ※アーキタイプにより大きく変わる。詳細は `deck-archetypes.md`。

## 2. タイトルとメッセージの分離（アクションタイトル）

「タイトル（見出し＝何について）」と「メッセージ（結論の一文＝何を言いたいか）」は階層が違う。**混同しない**。

- **メッセージ（結論の一文）は体言止めを避け、主語・述語を備えて言い切る**。
  見出しを見て「だから何？（So What?）」に答えられなければ、それは結論ではなく単なるテーマ。
  - ✗「市場動向」→ ○「市場は3年で2倍に拡大する」
  - ✗「クラウド評価の位置付け」→ ○「クラウド評価は最大の基盤として情報を次のプロダクトへ渡す」
- 日本語は主語を省きがちで、それが論理の甘さを助長する。**全メッセージに主語を入れる**。
- 補足: 「タイトル（見出し）レベルは体言止めが簡潔で良い」とする実務流派もある。これは見出しの慣習であり、
  結論文とは階層が異なる。**このスキルでは「アクションタイトル＝主張を言い切る文」を既定**とする。
- スライド構成案では、各スライドのタイトル欄にこの「アクションタイトル案」を書く。目次語で埋めない。

## 3. MECE とグルーピング

- **MECE**（相互に排他的・全体として網羅的）で情報の重複・漏れ・ずれを防ぐ（横の論理）。
  重複＝頭が整理されていないサイン、漏れ＝一点の弱点が全体の説得力を崩す、ずれ＝テーマ逸脱。
- **代表的な切り口**: 時間軸（過去/現在/未来・短期/中期/長期）、効率・効果、量・質、事実・判断。
- 厳密な分解が難しくても、**大きく括ってタイトルを付ける**ことで全体像を見せる意味がある。
- **同一階層の並べ方**: 時系列順 / 構造順（全体→部分）/ 重要度順（最重要→補足）の 3 パターンが基本。

## 4. So What? / Why So? による検証

- **Why So?（なぜ？）**: 結論に対し根拠が正しいかを下向きに検証。
- **So What?（だから何？）**: 根拠（事実）から何が言えるかを上向きに検証。
- ピラミッドの各階層で、上位が下位群の要約（So What?）になっているか、下位群が上位の根拠（Why So?）として十分かを
  縦に往復して検証する。
- 「観察の So What?」（事実群から読み取れること）と「洞察の So What?」（さらに引き出す示唆）を区別する。

## 5. ストーリーフレーム（構成の型）

構成を複数案つくるとき、性格の異なるフレームを当てて語り口を変える。

| フレーム | 流れ | 効く場面 |
| --- | --- | --- |
| **SCQA** | Situation（同意できる現状）→ Complication（変化・問題）→ Question（自然に生じる問い）→ Answer（結論） | 導入で関心を勝ち取りたい。提案・戦略発表の冒頭 |
| **空・雨・傘** | 空＝事実（解釈を混ぜない）→ 雨＝解釈・仮説 → 傘＝行動・結論 | 事実と判断を切り分けて示す。分析報告・意思決定 |
| **課題→原因→解決→効果** | 課題提起 → 原因分析 → 解決策 → 効果 | 営業提案・企画。解決策の必然性を出す |
| **PREP** | Point → Reason → Example → Point | セクション/スライド単位の結論先出し |
| **並列型（帰納）** | 同格の論拠を複数並べて結論を支える | 網羅性で押す。論点整理 |
| **解説型（演繹）** | 一つの論点を掘り下げて結論に至る | 深さで納得させる |
| **論点網羅型** | 論点を MECE に並べ、各論点の結論を積む | 読み物・配布資料。抜け漏れなく検討したことを示す |
| **時系列型** | 過去 → 現在 → 未来（沿革・ロードマップ） | 経緯や計画を追う。勉強会・進捗共有 |
| **結論→根拠→選択肢型** | 結論 → 根拠 → 取りうる選択肢（2案提示） | 決裁・意思決定。判断を仰ぐ |

- ストーリーは資料作成の**先行工程**。①言いたいことを書き出す → ②聞き手が理解・行動しやすい順に並べ替える（ストーリー化）→ ③スライド化。
  構造化は「創造」ではなく「整理」。
- 感情面の流れ（社外プレゼン）: **共感 → 信頼 → 納得 → 決断**。開始 30 秒で共感を作る（「数字×質問」が強い）。
- 反復で定着させる: 予告 → 本論 → まとめ。重要メッセージは形を変えて複数回触れる。

## 6. 聴衆・目的に応じた出し分け

- 設計の基本軸は **目的（聞き手にどう行動してほしいか）と聴衆**。まず「承認を得る/行動を促す/理解させる/印象づける」を確定。
- **決裁者・経営層**: 時間がない前提でトップダウン（結論から）。歩留まりを意識し、無駄を削り結論到達を最短化。
  決裁では ①財務的視点 ②実現可能性 ③理念との整合 を押さえる。**2案提示**は採択が進みやすい。
- **現場・初見の関係者**: ボトムアップ（背景から積み上げ合意形成）が効く場面もある。
- **社外・海外**: 出所不明の情報は信用されない。数値・主張に**出典**を付ける。

## 7. 出す前のチェックリスト

構成案をユーザーに提示する前に自己検証する。

- [ ] **水平ロジック**: タイトル（アクションタイトル）だけを上から繋げて読み、全体の主張が通るか。
- [ ] **垂直ロジック**: 各スライド内の要素がそのタイトルを裏付けているか。
- [ ] **1スライド1メッセージ**: 2主張が入っているスライドはないか（あれば分割）。
- [ ] **MECE**: セクションの分け方に重複・漏れ・ずれがないか。
- [ ] **結論先出し**: 聞き手の型（決裁者/現場）に対しトップダウン/ボトムアップが合っているか。
- [ ] **出典**: 数値・引用に出典欄が用意されているか。
