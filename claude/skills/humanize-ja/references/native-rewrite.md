# 作り直しモード — 日本語ネイティブとして書き起こし直す

最もアグレッシブなモード。翻訳調の骨格ごと表層を捨て、意味だけを取り出して、日本語ネイティブが一から書いたように書き起こす。他の 3 モード（軽い手直し・標準・再構成）が原文の文をベースに直すのに対し、作り直しは **原文の日本語文を手本にしない**。手本にすると英語の骨格を引きずるからだ。

## いつ使うか / 使わないか

**使う。** AI が出力した翻訳調テキスト。無生物主語（「このツールは〜を可能にする」）、翻訳構文（「X は Y することで Z を実現する」）、英語エッセイ的な段落構造（全段落が topic sentence 始まりで同じ呼吸）が残り、文単位の手当てでは骨格が抜けない文章。文法は正しいのに、リズムと発想だけ英語のままの文章。

**使わない。** 人が書いた文章、一次体験・主観・固有の語り口が濃い文章。作り直しは著者の声ごと塗り替えるため、守るべき声がある原文では損失が大きい。そういう原文は標準・再構成に留める。原文の由来や声が読めず判断に迷う場合は、標準・再構成にするか、ユーザーに一言確認する。

**背骨は変わらない。** 表層を全部書き直してよいが、意味・事実・数字・主張・専門用語・固有名詞・読み取れるスタンスは 1 ミリも変えない・足さない・落とさない。緩めるのは「原文の言い回しを残す」だけで、「意味と事実は変えない」は他モードと完全に同じ。

## 基本方針 — 3 工程で進める

文単位でチマチマ直すのではなく、次の 3 工程で進める。

### 工程 1. 意味の抽出（コンテンツ・スケルトンを作る）

原文を読み、伝えている中身だけを日本語の箇条書きで抜き出す。**ここで原文の語順・構文・言い回しは一切引きずらない。** 英語の骨格はこの時点で捨てる。抜き出すもの：

- **主眼** — 何を伝える文章か（一言で）
- **事実・数字・データ** — 落とせない情報を漏れなく
- **主張とスタンス** — 何を言い切っているか。断定か、推量・留保付きか
- **専門用語・固有名詞** — 原文の表記のまま控える（保護対象）
- **論理の順序** — 原文の骨子が良ければ踏襲、崩れていればサビ頭で組み直す

### 工程 2. 日本語で書き起こす

スケルトンだけを見て書く。原文の日本語文はできるだけ見ない（見ると英語骨格を引きずる）。日本語ネイティブの発想で書く：

- 主語は文脈で分かるなら省く。人を主語にする。無生物主語を避ける
- 動詞で言い切る。名詞構文（「〜の実現」「〜の向上」）を動詞に戻す
- 一文一義。サビ頭。文末に変化をつける
- **英語で多用される語彙（provide／leverage／ensure などの直訳）を平易な日本語に置き換える**（→「英語で多用される語彙の置き換え」節）
- 媒体のトーンに合わせる（→ `tone-by-genre.md`）
- 全面書き直しなので、`writing-principles.md` の原則をフルに適用してよい

英語骨格の具体的な組み替えは次の 2 つの表を使う。構文レベルは「英語骨格の症状」、語彙レベルは「英語で多用される語彙の置き換え」。

### 工程 3. 突き合わせ検証（必須・飛ばさない）

書き起こした文を原文と照合する。全面再生成は **欠落・捏造・専門用語ずれのリスクが最も高い**。この工程が、アグレッシブな書き換えを背骨につなぎ止める安全弁。末尾の検証チェックリストで点検し、ずれがあれば直す。具体で書けない箇所は水増しせず申し送る。

## 英語骨格の症状と日本語への組み替え

この表が作り直しの実務の中心。翻訳調の深い癖を、日本語の発想へ組み替える。（浅い翻訳調は `ai-tells.md` 8 節・14 節も参照）

| 英語骨格の症状 | 日本語への組み替え |
|---|---|
| 無生物主語（「このツールは〜を可能にする」「本機能は〜を提供する」） | 人を主語にする／主語を省く（「このツールを使えば〜できる」） |
| 翻訳構文「X は Y することで Z を実現する／可能にする」 | 動詞中心で（「Y すれば Z できる」）。使役・可能の入れ子をほどく |
| 過剰な主語明示（英語は主語必須／総称の you・we） | 文脈で分かる主語・「あなた」「私たち」は省く |
| 名詞構文・動作の名詞化（「〜の実現」「〜の向上」「〜の構築」「〜の最適化」） | 動詞に戻す（「実現する」「高める」「作る」「見直す」） |
| 後置修飾の直訳（関係代名詞的な長い「〜する、〜な X」） | 修飾を前に出す／二文に割る |
| 論理コネクタの過剰明示（therefore／however／moreover を律儀に訳す） | 無くて通じる順接（したがって・さらに・また）は削る。逆接は残す |
| パラレル構造の機械反復（First… Second… Third…／「それは〜」の連呼） | まとめる・崩す。「第一に／第二に」の足場を外す |
| not A but B の連発（「〜ではなく〜だ」） | 肯定文で直接述べる。要所だけ対比を残す |
| 英語エッセイ段落（全段落 topic sentence 始まり・同じ呼吸） | サビ頭にして段落の役割に緩急をつける |
| カタカナ語の過剰 | 平易な和語・漢語で足りるものは開く。**定着した専門用語・製品名のカタカナは残す** |
| 「〜的」「〜性」「〜化」の乱発 | 具体的な動詞・名詞に（「効率的に」→「速く」「ムダなく」） |
| 指示語の連発（these／those を「これらの／それらの」で機械訳） | 削る／具体名に戻す |
| 受動態の羅列（「特定され、分析された」） | 能動態で、行為者を主語にする（「調べて特定した」） |

**カタカナの線引き。** 置き換えるのは、平易な和語・漢語で同義になる冗長なカタカナだけ。製品名・技術用語・業界で定着した語（アーキテクチャ、ガバナンス、コンプライアンス等）は原文の表記のまま残す。判断に迷うカタカナは残す側に倒す（→ 大前提 2「専門用語と固有名詞は保護する」）。

## 英語で多用される語彙の置き換え

英語では高頻度で使う「万能動詞」や抽象名詞が、直訳で硬い漢語・カタカナのまま日本語に残るのも英語くささの正体。日本語ネイティブはもっと平易な語を選ぶ。作り直しモードでは、これらを疑って置き換える。前節が構文の癖なら、この節は語彙の癖。

**英語発の万能動詞（オペレータ動詞）**

| よく訳出される英語 | 直訳調（AI が出しがち） | 自然な日本語 |
|---|---|---|
| provide / offer | 提供する | する／出す／載せる／用意する／〜がある |
| enable / allow | 可能にする | 〜できる（主語を人にする） |
| leverage / utilize | 活用する | 使う／生かす |
| ensure / guarantee | 確保する／担保する | 必ず〜する／〜するようにする／守る |
| facilitate / promote | 促進する | 進める／後押しする／〜しやすくする |
| enhance / improve | 強化する／向上させる | 高める／良くする／上げる |
| address / tackle | 対処する／取り組む | 解決する／片づける／向き合う |
| achieve / realize | 実現する／達成する | 成し遂げる／〜する／届く |
| optimize | 最適化する | 無駄をなくす／うまく調整する／速くする |
| drive | 推進する／牽引する | 進める／引っぱる |
| foster / cultivate | 醸成する／育む | 育てる／根づかせる |
| empower | 力を与える／エンパワーする | 〜できるようにする |
| unlock | 解き放つ／引き出す | 引き出す／使えるようにする |
| establish | 確立する | 作る／築く／決める |
| identify | 特定する | 見つける／突き止める |
| explore | 探求する／模索する | 調べる／試す／考える |
| support | サポートする | 支える／助ける／対応する |

**英語発の抽象名詞・バズワード**

| よく訳出される英語 | 直訳調 | 自然な日本語 |
|---|---|---|
| solution | ソリューション | 解決策／製品／サービス（何を指すか具体に） |
| value | 価値 | 役立つこと／メリット（具体に） |
| experience | 体験／エクスペリエンス | 使い心地／使いやすさ |
| insight | インサイト／知見 | 気づき／分かったこと |
| journey | ジャーニー／旅 | 道のり／流れ／過程 |
| ecosystem | エコシステム | 仕組み／全体 |
| landscape | ランドスケープ／全体像 | 状況／全体 |
| impact | インパクト | 影響／効果（具体に） |
| capability | ケイパビリティ／能力 | できること／機能 |
| robust | ロバストな／堅牢な | 壊れにくい／安定した |
| seamless | シームレスな | 途切れない／なめらかな／手間なく |
| scalable | スケーラブルな | 拡張しやすい |

**英語発の枠組み・接続表現**

| よく訳出される英語 | 直訳調 | 自然な日本語 |
|---|---|---|
| in the context of | 〜という文脈で | 〜では／〜のとき |
| in terms of / from the perspective of | 〜の観点から | 〜で／〜について（多くは削る） |
| with respect to / regarding | 〜に関して | 〜は／〜について |
| it is important to note that | 重要なのは〜という点だ | （多くは削って直接述べる） |
| it is worth noting | 特筆すべきは／言及に値する | （削る／「〜も」で軽く添える） |
| tend to | 〜する傾向がある | 〜しがち／たいてい〜する |

**線引き（この節も背骨を守る）**
- これは「悪い語」リストではなく「英語直訳のサイン」。文脈でその語が最適なら残す。機械的な一括置換はしない。
- **専門用語・製品名・業界で定着した語は保護する。** 会議・意思決定の「検討する」、技術文脈の「実装する」「フレームワーク」、UX 分野の「体験」など、その語が正しい術語である場合は残す（→ 大前提 2）。
- 置き換えで意味が変わる・ぼやけるなら置き換えない。同義に収まる範囲でだけ平易にする。

## 段落まるごとの before → after

**無生物主語 + 名詞構文 + パラレル反復**
- Before: 当社のソリューションは、データの一元管理を実現することにより、意思決定の迅速化を可能にします。また、リアルタイムでの可視化を提供することで、業務プロセスの最適化に貢献します。さらに、セキュアな基盤の構築を通じて、コンプライアンスの強化を支援します。
- After: 当社のサービスを使えば、散らばっていたデータを一か所にまとめられます。判断材料がそろうので、意思決定が速くなります。状況をリアルタイムで把握できるため、業務プロセスの見直しにも役立ちます。基盤のセキュリティも固めてあり、コンプライアンスの強化につながります。
- 保った中身：一元管理→意思決定の迅速化／リアルタイム可視化→業務プロセスの見直し／セキュアな基盤→コンプライアンス強化。無生物主語「ソリューションは」を外し、「〜の実現／向上／構築」の名詞構文を動詞に戻し、「また／さらに」の足場を減らした。

**英語エッセイ構造 + 第一/第二/第三 + 総称の「私たち」**
- Before: 効果的なコミュニケーションは、成功するプロジェクトの基盤です。第一に、それは関係者間の期待値の調整を可能にします。第二に、それは問題の早期発見を促進します。第三に、それはチームの結束を強化します。したがって、私たちはコミュニケーションへの投資を優先すべきです。
- After: プロジェクトを成功させたいなら、まずコミュニケーションに投資すべきです。関係者どうしで期待値をすり合わせておけば、認識のズレが減ります。問題の芽も早く見つかり、チームもまとまります。
- 保った中身：期待値の調整／問題の早期発見／チームの結束の 3 点と、「コミュニケーションへの投資を優先すべき」という主張。結論をサビ頭に上げ、「第一に/第二に/第三に」「それは」「したがって」の英語骨格を外した。

**英語発の語彙の置き換え（万能動詞・抽象名詞）**
- Before: 本ソリューションは、最新のテクノロジーを活用することで、お客様のビジネスに新たな価値を提供し、成長を促進します。
- After: この製品は、最新の技術を生かして、御社の事業に新しいメリットをもたらし、成長を後押しします。
- 置き換えた語彙：ソリューション→製品／テクノロジーを活用する→技術を生かす／価値を提供する→メリットをもたらす／促進する→後押しする。無生物主語「本ソリューションは」も外した。中身の薄さ（「新たな価値」が何か）はこれ以上でっち上げず、必要なら申し送る。

**後置修飾 + 受動態 + 推量の保持**
- Before: 本レポートでは、近年急速に採用が進んでいる、クラウドネイティブなアーキテクチャへの移行に伴う課題が分析されている。それらの課題は、適切なガバナンスの欠如によって引き起こされていると考えられる。
- After: 近年、クラウドネイティブなアーキテクチャへ移行する企業が急増しています。本レポートは、その移行で生じる課題を分析しました。課題の原因は、ガバナンスの不備にあると見ています。
- 保った中身：分析対象（移行に伴う課題）と、原因の推定（ガバナンスの欠如）。専門用語「クラウドネイティブなアーキテクチャ」「ガバナンス」はカタカナのまま保護。受動態「分析されている／引き起こされている」を能動に。**「考えられる」の推量は「と見ています」で残し、断定に格上げしない**（→ `ai-tells.md` 9 節）。

## 検証チェックリスト（工程 3）

書き起こしたら、原文と照合して次を確認する。ひとつでも崩れていたら直す。

- [ ] 原文の**事実・数字**が全て残っているか（書き起こしで落としていないか）
- [ ] 原文に**無い事実・数字・主張・具体例を足していないか**（滑らかに書くための捏造がないか）
- [ ] **専門用語・固有名詞**の表記と意味がずれていないか。カタカナ語を過剰に開いて意味をぼかしていないか
- [ ] **主張の強さ**（断定／推量／可能性／仮定）が原文と一致しているか。ヘッジを削りすぎて断定に格上げしていないか
- [ ] **因果関係**が原文と同じ向き・同じ結び付きか（別々の原因と結果を取り違えていないか）
- [ ] 原文の**スタンス**（賛否・推し・留保）を勝手に変えていないか
- [ ] 具体で書けなかった抽象箇所を、水増しでごまかしていないか（→ 申し送る）
- [ ] **英語発の語彙**（提供する・活用する・確保する・促進する・ソリューション等）が直訳のまま残っていないか。平易な日本語で足りるのに硬い漢語・カタカナを使っていないか（→「英語で多用される語彙の置き換え」節）
- [ ] 媒体のトーン（→ `tone-by-genre.md`）から外れていないか

検証を通したら、`SKILL.md` ワークフロー 5 の推敲（意味・字面・語呂）とセルフ監査を他モードと同様にかける。
