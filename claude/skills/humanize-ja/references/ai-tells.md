# AI くささの症状カタログ

AI が生成した日本語に頻出する症状を、カテゴリ別に before→after で示す。診断時はこの観点で原文を走査する。各症状の根っこは「具体性がなく、削れる語が多く、リズムが均質」の三つに集約される。

## 1. 構成・段落のクセ

- **過剰な箇条書き化。** 散文で流れるべき内容まで箇条書きにし、各項目が「名詞 + 説明」で粒度バラバラ。→ 関連する 2〜3 点は文にまとめる。箇条書きは「並列で、順不同で、各項目が独立して読める」ときだけ使う。用語と定義の列挙は箇条書きでよい。
- **段落ごとの三段構成。** どの段落も「結論→理由→まとめ」を律儀に繰り返し、文章全体が同じ呼吸で単調。→ 段落の役割を変える。要点提示の段落、具体例の段落、転換の段落で緩急をつける。
- **網羅志向・三点セットの強制。** 「メリット・デメリット・注意点・まとめ」と機械的に揃える。理由や例が不自然に必ず 3 つになる。→ 主眼に沿って取捨選択する。2 つで足りるなら 2 つでよい。
- **構造の宣言癖。** 「以下の 3 つの観点から説明します。それぞれ順に見ていきましょう」。見出しで分かることを本文で再宣言する。→ 削っていきなり中身に入る。
- **ステップ／STEP 乱発。** 方法論を必ず「ステップ 1：〜」形式に落とす。→ 手順として本当に順序が効くときだけ。散文で流せるなら文にする。
- **場面の直後の要約し直し。** 具体例を描写した直後に、同じ内容を抽象語で要約し直す。→ 意味づけの一文だけ置くか、何も足さない。

## 2. 前置きと締めのクセ

AI 文章で最も目立つ症状。**前置きと締めは、ほとんどの場合まるごと削れる。** セルフ監査でも冒頭と結論を最優先で点検する。

- Before: 本記事では〜について詳しく解説していきます／ご紹介します。
- Before: まず最初に、〜の基本から見ていきましょう。
- Before: ご質問ありがとうございます。〜は現代のビジネスにおいて非常に重要なテーマです。（チャットボット応答の残留）
- Before: いかがでしたでしょうか。／本記事が参考になれば幸いです。／ぜひ試してみてください。
- Before: 今後の展開が注目されます。／まずは小さく始めましょう。（定型的な結論パターン）
- After: いずれも削除。本論をサビ頭で始め、締めは「次の一手」を具体的に示すか、何も足さない。

**「結論から言うと」なのに結論が薄い** のも典型症状。出だしだけ強気で、続く内容が「状況に応じて最適な方法は異なります」では結論になっていない。→ ラベルを外し、中身のある結論を先頭に置く。書けるだけの根拠が原文にないなら、その旨を申し送る。

## 3. 冗長表現

意味を変えずに削れる定型。

| AI くさい | 自然 |
|---|---|
| 〜することができます | 〜できます |
| 〜という形になります／〜となっております | 〜です／〜になります |
| 〜していきたいと思います | 〜します |
| 〜する必要があります | 〜が必要です／〜しましょう |
| 〜することが可能です | 〜できます |
| 〜を行います | 〜します |
| 〜についてですが | 〜は |
| 〜に関しまして | 〜について／〜は |
| 〜という点において | 〜で |
| 〜であると言えるでしょう | 〜です |
| まさに〜と言っても過言ではありません | （削除して言い切る） |

## 4. 抽象語・空疎語の水増し

具体の代わりに置かれる「それっぽいが情報量ゼロ」の語。原文に根拠があれば具体へ。なければ強調だけ削って残す。

- さまざまな／幅広い／多岐にわたる／あらゆる
- 最適な／最良の／効果的な／革新的な
- 重要な／大切な／不可欠な／核心的な／鍵となる／根本的な（強調だけで中身がないとき）
- 多角的／包括的／総合的（何をどう見たかを書かない）
- ニーズ／ソリューション／価値／体験／本質（中身を伴わない名詞）
- 〜の最適化／〜の向上／〜の実現／価値を最大化（何をどうするか不明なとき）

例：
- Before: さまざまな課題に最適なソリューションを提供し、お客様の価値向上を実現します。
- After: 監査ログの確認に毎月かかっていた 2 日を、自動レポートで半日に短縮します。

**評価語が強いのに根拠がない** のも同類。「非常に有効です」「大きなメリットがあります」と強く評価するのに、なぜそう言えるかが書かれていない。→ 根拠が原文にあれば根拠ごと具体で書く。なければ評価を弱めるか削る。

**曖昧な出典への言及** も水増しの一種。「専門家によると」「研究で示されています」「〜と言われています」で出典を特定しない。→ 出典が原文にあれば明記し、なければ主張の帰属を著者に戻すか、確認が要る旨を申し送る。確認していないことを確認したかのように滑らかに書かない。

## 5. 接続詞・メタ表現・LLM 空句

論理を語で繋ぎすぎて、かえって読みにくい。

- 連打されがち：まず／次に／そして／さらに／また／加えて／したがって／このように／つまり／なお
- → 接続詞は「無くて意味が通るなら消す」。逆接（しかし・ただし）は残し、順接（そして・また・さらに）は削れることが多い。文章のリズムを作るための接続表現（「しかし一方で」など）は冗長と見なさない。
- メタ表現（文章について語る表現）も削る：「ここで重要なのは」「先ほど述べたように」「以下で説明します」。

**LLM 空句**——論点を増やさず「ちゃんと書いている感」だけを付ける言い回し。見つけたら中身に置き換えるか削る。

- **予告と総括**：「重要なのは〜である」「本章では〜を扱う／探求する」「ここでは〜について見ていく」「まとめると」「要するに」（直前の言い換えだけのとき）「〜に他ならない」
- **姿勢の宣言**：「正面から扱う」「正面から向き合う」——中身の代わりに姿勢だけを述べる
- **空虚な動詞**：「掘り下げる」「深掘りする」「言語化する」（何をどう書いたか示さない）「触れる」「言及する」（一段落で済ませるだけ）
- **接続の型**：「〜において」「〜という側面から」「〜の観点から」（新情報がないとき）

悪い例：「多角的に分析すると、重要なのは〜である」。良い例：「評価の核心は、正しさを誰が知っているかにある」——主張をそのまま書く。

## 6. 強調語・修飾語の乱用

- 乱用語：非常に／とても／極めて／大いに／しっかりと／きちんと／まさに／本当に／圧倒的に
- → 強調語は中身を強くしない。多くは削る。強調したいなら具体（数字・事実）で示す。
  - Before: 非常に高いパフォーマンスをしっかりと発揮します。
  - After: 同等構成の従来比で処理速度が 2.3 倍になります。
- **意義の過剰な強調。** 事実を述べるたびに「これは極めて重要な意味を持ちます」と意義を上乗せする。→ 事実はそのまま置く。読者は自分で意味を読み取れる。

## 7. 文末・リズムのクセ

- **同じ文末の連続。**「〜です。〜です。〜です。」が続くと AI くさく単調。→ 同じ語尾を 3 つ続けない。体言止め・問いかけ・「〜ます／〜ません／〜でしょう」などで変化をつける。ビジネス文では敬体を基調に保ちつつ崩す。
- **左右対称で抑揚がない。** 一文の長さが揃いすぎ。→ 短文と中文を混ぜる。短い言い切りを要所に置く。
- **文章の温度が一定。** 重要なところも軽い補足も同じテンションで書かれ、サビが分からない。→ 山場は文を短く強く、補足は軽く流す。強弱をつける。
- **段落の閉じ方が毎回同じ。** 「以上がポイントです」「次に進みましょう」と、どの段落もきれいに閉じて読後の余韻が均一。→ 閉じの一文を削り、言い切りや具体で終える段落を混ぜる。
- **not A but B 構文の連発。** 「これは〜ではありません。〜です」「A ではなく B」が数行に一度出てくる。1 回なら効くが、続くと機械的。→ 対比が本当に効く要所だけ残し、他は肯定文で直接述べる。「A ではなく B」と否定するときは、否定の根拠を一文添える。
- **時制が現在で固定。** → 過去・現在を適度に混ぜると推進力が出る（『新しい文章力の教室』）。

## 8. 語彙・言い換えのクセ

- **同義語の不自然な使い分け（同義語循環）。** 同じ対象を「ツール」「ソリューション」「プロダクト」と言い換えて統一感を欠く。「重要・大切・欠かせない」を並べて同じことを三度言う。→ 一つの呼称・一度の言い切りに統一する。専門用語・製品名は原文どおり。一度導入した術語はその語で通し、「AI」「ツール」のような曖昧語に後退しない。
- **翻訳調。**「〜は、〜することによって、〜を可能にします」のような英文直訳的構文。→ 主語を立て、動詞で言い切る日本語の語順に直す。
- **受動態の羅列。** 「特定され、判明した」のような結果の羅列。→ 行為者を主語にした動作の連なりで書く（「ログを調査して特定した」）。
- **過度な丁寧。**「〜させていただいております」の多用。→ 一段下げて「〜しています」。

## 9. 事なかれ表現（ヘッジ）— 削る基準と残す基準

AI は安全側に調整されているため、逃げ道になる枕詞・中立の装い・弱い否定を多用する。ただし **推量・可能性の表現を機械的に断定へ変えてはいけない**。次の基準で判定する。

**削る（根拠なく主張を弱めているだけ）**
- 「一概には言えませんが、一般的には有効だと考えられます」→ 「有効です」（本文に根拠があるとき）
- 「〜と言えるでしょう」「〜かもしれません」が、本文内の根拠で命題が確定しているのに添えられているとき
- 「ケースバイケースです」「状況によって異なります」で終わり、判断材料を示さないとき → どちらか一方を選ぶ条件を書くか、原文に材料がなければその旨を申し送る
- 「メリットもあればデメリットもあります」の中立止まり → 原文に判断が読み取れるなら、どちらが大きいかまで言い切る
- 「あまり推奨されません」「注意が必要です」の弱い否定 → 本当に禁止なら「〜しないでください」と言い切る

**残す（不確実性が事実として存在する）**
- 未確認の可能性、推定、仮定、反実仮想、読者が抱きそうな疑念を表すとき。「提示し続けているかもしれない」を根拠なく「提示し続けている」に変えない。不確実なら「〜の可能性があります」と文だけ整える。
- 検出・保証・解決を「必ず」「完全に」できるかのように書かない。条件付きで正確に述べる（「〜しやすい」「〜できることが多い」）。
- 何かを否定・限定するときは、否定する命題を正確に書き出す。「何もかもが解決するわけではない」のような漠然とした否定で済ませない。

要するに：**言い切れる根拠があるなら言い切る。ないなら不確実性を正確に残す。** どちらでもない水増しヘッジだけを削る。

## 10. 意義づけの付け足しと回りくどい繋辞

- **意義づけの付け足し構文。** データや事実を提示した直後に「これは〜を浮き彫りにしており」「〜を示唆しています」「〜の重要性を物語っています」と意義を接ぎ足す。→ 削る。データはデータとして置く。意味づけが必要なら、根拠に基づく一文で言い切る。
- **回りくどい繋辞（copula 回避）。** 「〜として位置づけられています」「〜の役割を果たしています」「〜となっています」——「〜です」で済む場面でわざわざ複雑な構文を使う。→ 「〜です」に戻す。
  - Before: SGLT2 阻害薬は、心不全治療において中心的な役割を果たす薬剤として位置づけられています。
  - After: SGLT2 阻害薬は心不全治療の中心的な薬剤です。

## 11. 定型比喩・チャットボット残留・追従トーン

- **定型比喩。** AI が好んで使う比喩の頻出リスト：地図／羅針盤（コンパス）／設計書／土台／柱／架け橋／栄養／筋トレ（筋肉）／DNA／車の両輪／潤滑油／エンジン／スパイス／レシピ。→ 指す内容が一意に決まらない比喩は平易な動詞でそのまま言う（「知識を体に入れる」→「身につく」）。比喩を残すなら、その文脈でしか成立しない固有の比喩に。
- **チャットボット残留表現。** 「ご質問ありがとうございます」「お役に立てれば幸いです」「他にご不明な点があればお知らせください」——対話の応答がそのまま文章に残っている。→ 全削除。
- **追従的・お世辞的トーン。** 「素晴らしい視点ですね」「おっしゃる通り、〜は重要です」。→ 削除。文章は読者に媚びない。
- **想像上の読者との問答。** 「〜と思うかもしれません。そのとおりです」のような、問いを立てて自分で答える修辞。→ 主張をそのまま述べる。読者の疑問なら疑問文のまま書いてよい。

## 12. 体裁・記号のクセ

Markdown 記法や英語圏の記号習慣の残留は、最も分かりやすい AI の痕跡。詳細な統一ルールは `notation-rules.md`。

- **`**太字**` やアスタリスクの残留。** プレーンテキストに `**` がそのまま残る。→ 除去。太字が使える媒体でも機械的多用はしない（1 段落 1 箇所まで。乱発すると強調が無効化する）。
- **インラインヘッダー付き箇条書き。** 「- **速度:** コード生成が高速化」のような太字見出し + コロン形式。人間はあまりこう書かない。→ 文章に統合するか、太字とコロンを外す。
- **ダッシュ（—）での言い換え・挿入。** 「多角的な視点—すなわち〜」。→ 日本語の地の文ではダッシュを使わない。括弧か読点、または二文に分ける。
- **コロン直後の半角スペース。** 「重要な要素： テクノロジー」の「： 」。英語癖の残留。→ スペースを除く。そもそもラベル列挙（「目的：」「背景：」）自体を減らし、文で書く。
- **全角スラッシュ（／）での概念並列。** 「アクションプラン／戦略的優先事項」。→ 「と」「や」で繋ぐか、どちらか一方に絞る。
- **「」の切り出しすぎ。** 強調や定義のためのカギ括弧が多く、さらに「」の中に『』が入れ子になる。→ 引用・固有の呼称・否定する命題の明示など、機能がある箇所だけ残し、あとは文脈に溶かす。
- **（）の補足しすぎ・責任回避。** 補足を括弧に逃がし続ける。「（ただし状況によります）」のような括弧内の保険。→ 必要な補足は本文の一文に組み込み、保険は 9 節の基準で判定する。
- **見出しや箇条書き先頭の絵文字・記号の乱用**（✅🚀💡など）。ビジネス文書では原則外す。
- **中黒（・）での語の並列の多用。** → 読点や「と」で繋げるなら繋ぐ。単一の固有名詞内部の中黒はそのまま。

## 13. 頻出フレーズ早見表（見つけたら疑う）

いかがでしたか / 参考になれば幸いです / ぜひ〜してみてください
今後の展開が注目されます / まずは小さく始めましょう
ご質問ありがとうございます / お役に立てれば幸いです

さまざまな / 幅広い / 多岐にわたる / 最適な / 革新的な
重要なのは〜です / 〜に他なりません / 本質を押さえ / 価値を最大化
多角的 / 包括的 / 総合的 / 掘り下げる / 深掘りする
まず / 次に / そして / さらに / また / 加えて（連打）
非常に / とても / しっかりと / きちんと / まさに
〜と言えるでしょう / 〜と言っても過言ではありません
一概には言えませんが / 一般的には / ケースバイケースです
〜を浮き彫りにしており / 〜を示唆しています / 〜の重要性を物語っています
〜として位置づけられています / 〜の役割を果たしています

これらは「悪い語」ではなく「水増しのサイン」。文脈で本当に必要なら残す。機械的な一括置換はせず、意味を見て判断する。

## 14. なぜ AI はこう書くのか（診断の背景知識）

symptom を覚えるより、原因を知っておくと未知のパターンにも気づける。

1. **学習元の平均への回帰。** ビジネス文書の学習元はマニュアル・FAQ・規程・解説記事が多く、前置き・構造宣言・注意書き・まとめの繰り返しを持つ。AI はその平均的な型を最短で出すため、テンプレ色が濃くなる。
2. **安全調整の副作用。** 有害な断定を避けるよう調整された結果、「A という説もありますが B という側面もあります」と全方位に配慮した、判断の残らない文章になる。
3. **英語基盤の翻訳。** 英語の論理構造と英語圏のドキュメント文化（Markdown、箇条書き、コロン + 半角スペース、em ダッシュ）で骨組みを作って日本語化するため、文法は正しいのにリズムと記号だけ洋風になる。

つまり AI くささの正体は「テンプレの平均 + 全方位の保険 + 洋風の骨格」。直すときもこの 3 方向で考える：型を崩す、スタンスを戻す、日本語のリズムに直す。
